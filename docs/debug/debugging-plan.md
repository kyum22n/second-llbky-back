# DB 재연동/배포 후 발생한 문제 디버깅 계획

> 이 문서는 2026-09 진행된 포트폴리오·이력서 vs 실제 코드 정합성 검증(1단계) 과정에서 발견된 문제들과, DB 재연동/배포 작업 이후 사용자가 실제로 겪은 "브라우저에서 LLM 호출이 되지 않는다"는 문제를 함께 디버깅하기 위해 작성된 **계획 문서**입니다. 실제 수정 내용과 재현·검증 결과는 [debugging-result.md](debugging-result.md)에 기록했습니다.

## 배경

1단계 문서-코드 정합성 검증에서 `second-llbky-back`/`second-llbky-front`(Notion 포트폴리오 "AI 취업 컨설팅 서비스" 프로젝트에 해당)에 다음과 같은 문제들이 발견되었고, 사용자가 항목별로 수정 여부와 방식을 확정했습니다. 목적은 이미 동작 중인 기능을 건드리지 않는 선에서, 실제로 문제가 되는 부분만 최소 범위로 고치는 것입니다.

## 범위 및 항목별 방침

### P0-1. 로그인 실패 시 500 반환
- **원인**: `MemberService.login()`에서 아이디 없음/비밀번호 불일치 시 둘 다 `RuntimeException`을 던지는데, `GlobalExceptionHandler`에는 이를 처리하는 핸들러가 없어 미처리 예외 → 500으로 떨어짐.
- **방침**: 로그인 로직 자체는 그대로 두고, 예외 타입만 `GlobalExceptionHandler`가 이미 처리하는 타입(`NoSuchElementException`→404, `IllegalArgumentException`→400)으로 교체.

### P0-2. `insertCustomQuestion` 컬럼/값 개수 불일치
- **원인**: 매퍼 SQL이 컬럼 3개(`session_id, question_text, created_at`)에 값 2개만 제공해 SQL 문법 오류가 날 수 있는 상태였음.
- **확인된 사실**: 이 메서드는 어디서도 호출되지 않는 죽은 코드였고, 실제 "AI 질문 확인 후 사용자가 직접 질문 추가" 기능은 `InterviewService`가 AI 질문과 사용자 질문을 병합해 `insertInterviewQuestion` 하나로 저장하는 별도 경로로 이미 정상 동작 중이었음.
- **방침**: 기능 변경 없이 SQL만 형제 구문과 동일하게 맞춰 잠재적 SQL 에러만 제거.

### P0-3. `deleteAllGuides`가 `news_summary` 테이블을 삭제
- **원인**: 포트폴리오 가이드 전체 삭제 매퍼가 `delete from news_summary where member_id=...`로 하드코딩되어 있었음(다른 매퍼에서 복붙된 흔적).
- **방침**: 삭제 대상 테이블명을 `portfolio_guide`로 정정.

### P1-1. RAG/PGVector
- **사용자 확정**: 현재는 미사용이지만 확장을 위해 의도적으로 구현해둔 것. 코드/문서 변경 없음 — 산출물(포트폴리오 등)에 의도를 명시하는 것은 사용자가 직접 진행.

### P1-2. 학습 코칭 검증 로직 (검증 실패해도 저장됨)
- **원인**: `LearningDayService.submitMemo()`가 검증 결과와 무관하게 항상 `RewriteMemoAgent.execute()`를 호출했고, 그 안에서 valid/invalid 두 분기 모두 무조건 DB에 저장했음. 검증 실패 시에도 거부 안내 문구가 `learningDaySummary`에 그대로 저장되는 문제.
- **방침**: LLM이 생성한 거부 안내 메시지는 응답(화면 표시용)에는 유지하되, DB 저장은 검증 통과(valid)일 때로 제한.

### P1-3. 비언어 점수 로직
- **사용자 확정**: 현재 방식(LLM 프롬프트 지시문 기반) 그대로 유지, 수정하지 않음.

### P1-4. 기업 인재상 → 질문 생성 연계
- **확인된 사실**: `CompanyIdealTalentAgent`(인재상 조회)와 `CreateQuestionAgent`(질문 생성)가 완전히 분리된 API로, 인재상 데이터가 질문 생성 프롬프트에 전혀 전달되지 않았음.
- **방침**: 프론트엔드 변경 없이 백엔드에서 자동 연계 — `targetCompany`가 있으면 서버가 내부적으로 인재상을 조회해 질문 생성 프롬프트에 주입. 조회 실패 시에도 질문 생성 자체는 계속 진행.

### P1-5. 이력서 Skills 관련
- **사용자 확정**: 다른 프로젝트 기술까지 포함된 통합 목록이므로 무시, 산출물에도 포함하지 않음.

### P2. DB 재연동/배포 후 브라우저에서 LLM 호출이 전혀 안 되는 문제
- **최초 가설**: CORS 설정(`allowedOrigins("http://localhost")`, 포트 미명시)이 로컬 개발 서버 포트와 불일치할 가능성.
- **실제 재현 절차**: 로컬에서 `.env.local`의 실제 Neon DB/OpenAI 키로 백엔드·프론트엔드를 직접 구동해 브라우저로 실제 재현.
- **재현 결과, 최초 가설은 기각됨**: CORS·OpenAI 연동 자체는 정상(자기소개서 실시간 코칭 등은 200 정상 응답). 실제 문제는 두 갈래로 확인됨:
  1. **모의 면접 질문 생성**: PDF 파일을 첨부하지 않으면 프론트엔드(`interviewMock.js`)가 API 호출 자체를 하지 않고 `alert`만 띄우고 종료 — 네트워크 요청이 0건이라 "LLM 호출이 전혀 안 된다"는 증상과 정확히 일치.
  2. **트렌드 분석**: `SentimetalAnalysisAgent`의 시스템 프롬프트가 `.formatted(format)`을 호출하지만 실제 문자열에 `%s` 자리표시자가 없어, BeanOutputConverter의 "JSON만 출력하라"는 강제 지시문이 프롬프트에서 누락됨. 이 때문에 LLM이 (특히 분석할 뉴스가 없을 때) 자연어로 답하면 JSON 파싱이 실패하며 500 에러 발생.
- **연쇄 원인**: 뉴스가 애초에 하나도 수집되지 않는 이유는 네이버 뉴스/데이터랩 API가 401 Unauthorized를 반환하기 때문 — `.env.local`과 Render 환경변수 모두에 등록된 `NAVER_CLIENT_SECRET`의 형태(10자 Client ID 대비 40자 Secret)가 정상적인 네이버 자격증명과 달라 보임. 이 부분은 Naver Developers 콘솔에서 재확인/재발급이 필요하며, 값 자체를 다루는 영역이라 코드 수정 범위 밖.
- **방침(사용자 확정)**:
  - 모의 면접 PDF 필수 검증 제거 → 백엔드는 이미 `documentFile`을 `required=false`로 받고 있어 프론트 수정만으로 해결.
  - `SentimetalAnalysisAgent`의 `%s` 누락만 수정. JSON 파싱 실패 시 500으로 떨어지는 예외 처리 자체는 사용자 요청에 따라 그대로 유지.
  - 네이버 자격증명은 사용자가 직접 Naver Developers 콘솔에서 확인/재발급.

### P3. `src/utils/news.js`의 FIXME(하드코딩된 memberId)
- **확인된 사실**: 실제 코드는 이미 Vuex 스토어의 실제 로그인 memberId를 읽고 있었음 — 하드코딩이 아니었고, FIXME 주석만 과거에 작성된 뒤 갱신되지 않은 낡은 주석이었음.
- **방침**: 로직 변경 없이 낡은 FIXME 주석 한 줄만 삭제.

## 전체 기능 회귀 테스트 계획

수정한 항목뿐 아니라 인접 기능까지 포함해, 백엔드를 로컬로 구동한 상태에서 주요 기능을 직접 호출/조작해 정상 동작 여부를 O/X로 기록한다. 대상 범위는 회원(가입/로그인 성공·실패/정보수정), 자기소개서(코칭/저장/문체/목록/상세/수정/삭제), 면접(질문생성/커스텀질문/답변제출/피드백/세션저장), 학습(로드맵/메모 검증 통과·실패), 포트폴리오/포트폴리오가이드(등록/조회/삭제), 트렌드/뉴스(오늘뉴스/피드/검색/키워드), 이력서(생성/코칭/분석/리포트), 프론트 `/trend/news` 화면, 그리고 P2 핵심 검증인 "브라우저에서 LLM 호출 정상 완료" 여부다. 결과는 [debugging-result.md](debugging-result.md)에 표로 기록한다.
